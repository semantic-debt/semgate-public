## Additional finding

The original metric definition itself was invalid for v0.60 even after parsing was fixed. `decision=accept` cannot distinguish policy auto-allow from a one-time human acceptance. The corrected package logs the official `Notification` hook with `notification_type=ToolPermission` to count actual prompts. v0.60 still lacks a stable ID connecting that notification to its earlier `BeforeTool` event and later telemetry record. The package now reports the missing join rather than manufacturing a reduction percentage.

## Full review incorporation

The supplied 22.7 KB `REVISION.md` is preserved unchanged as `PRO-REVIEW-ORIGINAL.md`. Its additional claims were checked:

- **“Neutral output is not guaranteed” - confirmed.** Original input `[]` caused `AttributeError`; a directory log target caused `IsADirectoryError`. Revised `main` validates the input object, catches observation failures, writes a sanitized exception class to stderr, and emits `{}` with exit 0 in `finally`. - **Report files lacked explicit restrictive mode - confirmed.** Revised correlator chmods its output to 0600 on POSIX. Native Gemini telemetry remains governed by Gemini's exporter and local OS policy.
- **Installer comment support should use a real parser, not regex - partially confirmed.** Gemini uses `strip-json-comments`, not full JSON5. - **Deduplication by name did not update stale paths - confirmed.** Fixed: reinstall removes every prior `name: semgate-shadow` hook while preserving unrelated hooks/groups, then installs one current entry with the current absolute paths.
- **Shadow evaluation should preferably be asynchronous/post-capture - confirmed as architectural advice.** The revised synchronous Jev mode is optional, pinned, bounded, and off by default. Production shadow evaluation should move off the interactive hook path.
